### Frontend

- Engine: Supabase (PostgreSQL) OR MongoDB Atlas (using Mongoose)

### Artificial Intelligence
- API: Google Gemini API (@google/generative-ai)
- Security Enforcement: ALL AI API keys MUST strictly remain in backend .env files. NEVER expose keys on the frontend.

## 4. CORE FEATURES & IMPLEMENTATION STEPS

### Feature A: Authentication & Access Control
1. Implement JWT-based registration and login (/api/auth/register, /api/auth/login).
2. Secure password storage using bcrypt (10 salt rounds).
3. Validate request bodies using Zod schemas for email and password strength.
4. Protect secure API endpoints with an authMiddleware that verifies Bearer tokens.

### Feature B: Real-Time AI Payload Inspection (DLP Engine)
1. Build a POST route (/api/inspect/analyze) protected by JWT.
2. The endpoint receives payloadText (e.g., raw prompts, API payload strings).
3. Integrate Google Gemini API (gemini-1.5-flash) on the backend to:
   - Identify sensitive items (PII like names, emails, credit cards, or API keys).
   - Return a sanitized version with placeholders (e.g., [REDACTED_EMAIL]).
   - Categorize threat severity: LOW, MEDIUM, or HIGH.
   - Provide a brief compliance rationale.
4. Persist each inspection event in the database under an AuditLogs collection/table.

### Feature C: Privacy & Threat Analytics Dashboard
1. Endpoint GET /api/audit/stats to aggregate total threats intercepted, total PII redacted, and threat levels over time.
2. Frontend /dashboard page built with React + Recharts:
   - Top Stat Cards: Total Scans, PII Intercepted, Risk Score Index.
   - Area/Line Chart: Real-time payload inspection threat levels over time.
   - Table Component: Recent inspection logs with filtering by severity (HIGH, MEDIUM, LOW).

### Feature D: Interactive Payload Inspector Tool
1. Frontend /inspector page:
   - A dual-pane playground. Left: Input text area for user test payloads. Right: Real-time sanitized AI output + detected threats breakdown.
   - Submit button connected via Axios to /api/inspect/analyze.
